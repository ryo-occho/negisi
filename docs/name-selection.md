# 名前を選んで使う

アプリを開くと在籍スタッフの名前を表示します。自分の名前を選ぶだけで利用でき、メールアドレス・パスワード・招待・本人確認は行いません。画面内の「名前を変更」から選び直せます。ページを再読み込みした場合も名前を選ぶ画面から始めます。

希望と勤務はスタッフIDごとに保存されるので、別の端末でも同じ名前を選ぶと同じ内容を参照できます。るみ・ひろくんなど can_manage_shifts=true のスタッフ名を選ぶと「シフト作成」を利用できます。本人確認ではなく、選択した名前に応じた機能の切り替えです。

## 設定

ローカルは supabase/config.toml で匿名サインインを有効にしています。設定の変更後はローカルの認証サービスを再起動する必要があります。

本番へ反映する際は、追加マイグレーション staff_name_selection を適用し、Supabase Auth の匿名サインインを有効にします。匿名の端末セッション作成に必要なのでサインアップ全体は有効にし、メール・電話の認証は使用しません。SMTP・送信元メール・メール配信サービスの設定は不要です。アプリの公開も別途必要です。

## 希望調査の開始

希望調査の期間と提出締め切りは、シフト作成権限を持つ根岸（るみ）・ひろあきが設定して開始します。一般スタッフは開始済みの調査を選んで回答します。調査の作成・変更はDBの行レベル権限でも管理者に限定し、全スタッフの閲覧と自身の希望の提出は維持します。

## スタッフの登録

staff はメールアカウントと独立した名前の一覧になりました。信頼できる管理経路で display_name と active=true を登録すれば選択肢に表示されます。IDはDBが発行します。必要なスタッフだけ can_manage_shifts=true にします。利用停止は active=false にします。一般クライアントにスタッフの追加・権限の変更は許可しません。

既存スタッフのID・希望・提出内容・確定勤務は維持します。名前選択は staff_sessions に端末のセッションとスタッフIDの対応として保存し、既存のRLS・保存処理は選択中のIDを使います。まだ名前を選んでいない新規端末には、名前の一覧以外のデータを公開しません。従来の認証済みスタッフセッションは互換性のため本人のスタッフIDに解決できます。
