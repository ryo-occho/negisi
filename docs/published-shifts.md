# シフト作成と確定シフト

## シフト作成（るみ・ひろくん専用）

スマホでは日付を選ぶと昼・夜の候補を同じ画面に表示します。名前をタップすると選択・解除でき、希望に合う通常の割り当てには確認ダイアログを出しません。未提出・出勤不可のスタッフは候補に表示しません。「どちらも可」のスタッフは昼・夜両方の候補に表示し、両方に選ぶ場合だけ本人への確認を促します。昼・夜の割り当ては独立して保持します。

日付一覧に昼・夜それぞれの割り当て人数を表示します。

PCでは期間全体の表を初期表示し、希望を見ながらセル内の昼・夜をクリックして編集できます。スタッフごとの勤務日数も表示します。日付をクリックすると日ごとの候補選択に切り替わります。

希望や在籍状況が変わった割り当ては日別の「要確認スタッフ」に残し、解除できるようにします。公開前には期間全体の希望の要確認項目をまとめて表示します。

「下書き保存」は期間全体を二人だけの共有下書きとして保存します。「全員に公開」は期間全体を公開します。下書きの保存だけでは一般スタッフの画面は変わりません。公開後の訂正も同じ手順で行い、再公開するまでは前回の内容が表示されます。

二人の同時編集では、先に保存された内容を古い画面から上書きしないよう拒否します。「最新の内容を取得」で読み直してから編集してください。編集中の希望は自動更新しないため、最新の提出内容を確認する際も同じボタンで更新します。

## 確定シフト（全スタッフ共通）

「確定シフト」は公開済みの勤務を閲覧する画面です。日付ごと・スタッフ別の表を切り替えられ、30秒ごとに最新の公開内容を取得します。この画面には編集操作を表示しません。

## ローカル確認

マイグレーションを適用した後、既存のローカルシード手順で npm run db:seed を実行します。既存8名に、るみ・ひろくんを追加し、二人だけに can_manage_shifts=true を設定します。ログイン情報は .env.seed.local の SEED_RUMI_EMAIL / SEED_RUMI_PASSWORD、SEED_HIROKUN_EMAIL / SEED_HIROKUN_PASSWORD に保存されます。実アカウントやクラウドは変更しません。

1. るみでログインし、対象期間の「シフト作成」を開きます。
2. 希望を見ながら勤務を割り当て、下書き保存または全員に公開を選びます。
3. 一般スタッフで同じ期間を開き、閲覧できること、編集操作がないことを確認します。
4. ひろくんでも編集・公開できることを確認します。

## 権限とデータ

staff.can_manage_shifts は既定で false。一般クライアントに staff の更新権限はありません。権限は表示名で判定せず、信頼できる運用経路で UUID ごとに設定します。実スタッフ登録時は本人の Auth UUID を確認して権限を設定してください。

shift_schedule_drafts は二人だけの共有下書き、published_shifts は全スタッフ向けの公開済み勤務を保存します。どちらも版番号、最終更新者・日時を記録します。下書きの読み取り・作成・更新は在籍中で作成権限を持つスタッフのみ許可します。RLSで在籍者のみ閲覧、在籍中かつ作成権限を持つスタッフのみ作成・更新を許可します。未ログイン・未登録・利用停止のユーザーには公開しません。対象期間外、存在しないスタッフ、利用停止済みスタッフへの割り当てと重複はDBが拒否します。

権限と同時更新の回帰テストは supabase/tests/published_shifts_test.sql。npm run test:db で既存テストと合わせて実行します。
