# シフト希望データベース

## 対象

約12人、1店舗。希望の入力は本人のみ、閲覧は全員が可能です。確定シフトの作成・更新は staff.can_manage_shifts=true の在籍スタッフに限定します。
期間は同じ月の任意の開始日〜終了日（両端を含む）。1〜15日・16日〜月末のほか、1〜16日・17日〜月末などを作成できます。希望は昼 (`lunch`)、夜 (`dinner`)、どちらも可 (`either`)。
行がない日は出勤不可です。`either` は昼夜の両方に勤務する意味ではありません。
作成中のシフトは shift_schedule_drafts に、公開済みシフトは published_shifts に希望と分けて保存します。[確定シフトの仕様](published-shifts.md) を参照してください。

## テーブル

| テーブル           | 用途                                            |
| ------------------ | ----------------------------------------------- |
| staff              | Auth のユーザー ID、表示名、在籍状態            |
| shift_periods      | 期間の開始・終了日、提出期限、受付中フラグ      |
| shift_submissions  | 期間と本人ごとの提出日時。null は未提出・編集中 |
| shift_availability | 出勤可能な日と昼夜の希望                        |

日時は timestamptz、勤務日は日本の日付として date に保存します。
締め切りは対象期間開始日の日本時間0時以前に設定します。

## 権限

- 未ログイン、スタッフ未登録、利用停止済みのユーザーにはデータを公開しません。
- 在籍スタッフは全員の希望と提出状況を閲覧できます。
- 希望・提出状況の書き込みは本人のみ、受付中かつ締め切り前のみです。
- 対象期間の作成・受付変更は全スタッフが可能です。確定シフトの作成権限とは独立した操作です。
- スタッフの登録・利用停止は Supabase Dashboard などの信頼できる運用経路で行います。アプリから在籍状態を変更できません。
- Auth に登録しただけではスタッフになりません。公開サインアップは無効にする運用です。

## 希望保存と提出

1. 本人の shift_submissions を作成します（期間・本人の組は一意）。
2. 希望日だけ shift_availability に保存します。取り消す場合は行を削除します。
3. 最後に shift_submissions.submitted_at を現在時刻に更新して提出します。

希望を変更するとトリガーが提出日時を null に戻します。変更後は再提出が必要です。
全日出勤不可でも希望行を作らず提出日時だけ保存できます。
未提出と提出済みをこの日時で区別します。提出日時はクライアント指定の記録で、監査証跡ではありません。
期間の開始・終了日はデータベースで変更を禁止しています。必要なら新しい期間を作成します。

## ローカル開発・検証

Docker Desktop と Node.js が必要です。リポジトリのルートで実行します。

```sh
npm ci
npm run db:start
npm run test:db
```

CLI が生成した supabase/config.toml と migrations を利用します。
ローカルは自己登録を無効化しており、テストデータはテスト内で作成・ロールバックします。
クラウドにも migrations の SQL を適用します。Auth の「Allow new users to sign up」は Dashboard で無効化してください。
秘密キー・接続パスワード・実際のスタッフ情報はコミットしません。

## CI

`.github/workflows/ci.yml` が PR の作成・更新時と `develop` / `main` への push 時に、ESLint・Prettier と DB テストを別ジョブで実行します。
DB ジョブは `npm ci` → `npm run db:start` → `npm run test:db` の順で実行し、最後にローカル DB を停止します。
Supabase のアクセストークンやクラウド接続先の設定は不要です。
ローカル DB は他プロジェクトとの競合を避けるためポート55322（シャドー DB は55320）を使用します。

## 自由な期間の選択

画面上部で対象月・開始日・終了日を選びます。「登録済みの期間」から作成済みの受付も選べます。期間は開始日と終了日の組で一意です。開始日が同じでも終了日が異なる期間を別に作成でき、希望・確定シフトは期間ごとに独立します。既存期間の入力内容は自動で移し替えません。既存の期間の日付を直接変更することは引き続き禁止し、新しい期間として作成します。
