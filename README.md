# negisi

茨城県つくばみらい市の和食料理店「ねぎしや」で使う、スタッフ向けのシフト調整 Web アプリケーションです。
約12人のスタッフの希望シフトを集め、全員で希望を確認・共有できるようにします。確定シフトの決定方法は今後検討します。
アプリの販売や収益化を目的とせず、ねぎしやでの利用を想定しています。

## 現在の状態

開発準備段階です。リポジトリの基本構成と開発ガイドを用意しています。
Next.js の希望入力画面を Supabase Auth / Database に接続しています。スタッフのログイン、希望の保存・提出、全員の希望の閲覧に対応しています。利用開始には接続設定とスタッフ登録が必要です。
以下の機能と技術構成は開発予定です。

## シフトの運用

- スタッフは約12人です。
- シフトは半月ごとに決めます。
- 前半は毎月1〜15日、後半は16日〜月末を対象とする想定です。
- 例として、10月末に11月前半のシフトを決定します。
- 希望の提出期限や勤務時間帯などの詳細は、実際の運用に合わせて決めます。

## 初期開発で予定する機能

- スタッフのログイン（管理者ロールなし）
- スマートフォンからの昼・夜の希望提出・修正（未入力は出勤不可）
- 全スタッフによる提出状況と希望シフトの一覧確認
- シフトの調整・確定方法は別途検討
- スタッフによる公開済みシフトの確認

希望シフト、調整中のシフト、公開済みシフトを分けて管理し、編集途中の内容を誤って公開しない設計にします。

## 開発環境

Node.js 22 と Docker Desktop を使用します。`npm ci` で開発ツールをインストールしてください。`npm run dev` で起動し、http://localhost:3000 を開きます。`npm run build` で本番ビルド、`npm start` で本番サーバーを起動できます。
アプリの初期実装時に、必要なバージョンとセットアップ手順を追記します。

認証情報や実際の `.env` ファイルはコミットしないでください。
必要な環境変数は、秘密の値を含めず `.env.example` に記載します。
スタッフの個人情報や実際のシフトデータも公開リポジトリには含めません。

## 自動チェック（CI）

PR 作成・更新時と、`develop`・`main` への push 時に GitHub Actions が実行されます。

| コマンド               | 内容                                             |
| ---------------------- | ------------------------------------------------ |
| `npm run lint`         | ESLint による JavaScript / TypeScript のチェック |
| `npm run format:check` | Prettier による整形チェック                      |
| `npm run format`       | Prettier による整形                              |
| `npm run db:start`     | ローカル検証用 DB の起動とマイグレーション適用   |
| `npm run test:db`      | pgTAP のデータベーステスト                       |
| `npm run db:stop`      | ローカル DB の停止                               |

DB テストは `supabase/`、`package.json`、`package-lock.json`、CI ワークフローに変更がある場合に実行します。文書のみの変更では省略します。

DB テストには Docker が必要です。CI は一時的なローカル DB を使用し、クラウドのデータや秘密キーは使用しません。
ブランチ保護の必須チェックは別途 GitHub で設定します。
